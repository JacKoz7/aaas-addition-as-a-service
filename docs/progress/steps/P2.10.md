## Goal
`digit-7` in Gleam with its own SQLite database, following the reference
behaviour of `digit-0` (ADR-0022) and passing the shared contract test
`make contract-digit-7`. Result: digit 7.

## What Was Done
- **Service `services/digit-7`**:
  - Gleam 1.19.2 on Erlang/OTP 28. SQLite through `sqlight` and the
    `esqlite` NIF.
  - Scaffolded with `scripts/new-service.sh digit-7 gleam`, then given
    Gleam's layout (`src/`, `test/`, `dev/`).
  - `src/digit7/server.gleam`: an HTTP/1.1 server on `gen_tcp`. A chain
    of acceptor processes; each accepted connection is served by the
    process that accepted it.
  - `src/digit7/http.gleam`: the framing ported from `digit-6`:
    - line reading with a byte budget;
    - heads up to 8 KiB (431 above);
    - bodies by Content-Length or chunked, up to 64 KiB (413 above; 400
      for ambiguous framing);
    - keep-alive;
    - reply formatting.
  - `src/digit7/tracker.gleam`: an OTP actor that admits at most 256
    connections, monitors them, and drains them on stop.
  - `src/digit7/api.gleam`: the contract as a pure function, run by one
    contract process (an OTP actor) that owns the database and the
    counters.
  - `src/digit7/socket.gleam`: typed `@external` bindings to `gen_tcp`
    and `inet`, with a 16 KiB receive buffer. No Erlang source is added.
  - `src/digit7/signal.gleam`: a `gen_event` handler written in Gleam that
    turns SIGTERM into a message.
  - Also `src/digit7.gleam` (configuration and start-up checks),
    `store.gleam`, `metrics.gleam`, `log.gleam` and `trace.gleam`.
  - `migrations/0001_digit.sql`: table `digit` with the seed `7|7|8|0`.
  - `test/`: 56 gleeunit tests:
    - the contract and the database, on the real migrations;
    - the HTTP framing, on whole and split input;
    - the tracker and the signal handler;
    - the server, over TCP.
  - `dev/doc_coverage.gleam`: the documentation gate, built on the
    `glance` parser.
- **Image stages**:
  - toolchain: `erlang:28.5.0.8-alpine`, `build-base` and the Gleam binary
    (SHA-256 checked); Hex packages locked by `manifest.toml`;
  - lint: `gleam format --check`, `gleam build --warnings-as-errors`;
  - test: `gleam test`;
  - doc-coverage: `dev/doc_coverage.gleam` and `gleam docs build`;
  - api-docs: the `gleam docs` HTML;
  - build: `gleam export erlang-shipment`, plus the erts, kernel and
    stdlib parts of OTP;
  - runtime: Alpine 3.24.3 with libncursesw, libstdc++ and libgcc, user
    10001, emulator flags `+sbwt none`, `+P 4096` and `+Q 1024`; 59.3 MB.
- **Compose**: `digit-7` on the `services` network only, 128m, exec-form
  healthcheck, volume `digit-7-data`.
- **Repository**:
  - the `gleam` header type writes the header as a module comment
    (`////`), because `gleam format` moves module comments above it;
  - `scripts/lib/doc-definitions.psv` gets a `gleam` row;
  - `.doc-check-ignore` ignores `*/manifest.toml`.
- **Fix**: `services/digit-6/docs/SERVICE_CHARTER.md` named SwiftNIO,
  which ADR-0028 rejected; it now describes the server the service uses.
- **Documentation**: README, all ten documents of `CLAUDE.md` 6.5.5 with
  real content, API.md, ADR-0029.

## Decisions
- [ADR-0029](../../adr/0029-digit-7-gleam-on-gen-tcp.md):
  - Gleam with its own HTTP/1.1 server on `gen_tcp` instead of `mist`, for
    the limits of the earlier digit services;
  - OTP actors for the database and the connections;
  - SIGTERM through a `gen_event` handler written in Gleam;
  - Gleam's directory layout;
  - the module-comment header;
  - a reduced Erlang/OTP in the runtime image;
  - the `+P`, `+Q` and receive-buffer settings.
