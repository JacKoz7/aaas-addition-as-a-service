## Goal
`digit-2` in Fortran with its own SQLite database, following the reference
behaviour of `digit-0` (ADR-0022) and passing the shared contract test
`make contract-digit-2`. A thin HTTP wrapper is allowed if the digit logic
and the database access stay in Fortran (`CLAUDE.md` 4.4); the choice is
recorded in an ADR. Result: digit 2.

## What Was Done
- **Service `services/digit-2`** (Fortran 2018, gfortran 14, SQLite
  3.49.2), scaffolded with `scripts/new-service.sh digit-2 fortran`, with
  **no wrapper**: the HTTP server, the digit logic and the database access
  are Fortran; the C library is called through ISO_C_BINDING:
  - `src/posix.f90` and `src/sqlite.f90`: `bind(C)` interfaces (sockets,
    poll, signals, clock, directories, exit; the SQLite C API);
  - `src/http.f90`: HTTP/1.1 server, one connection at a time, one request
    per connection, head of at most 8 KiB within 500 ms, short drain after
    the reply, SIGTERM checked every 200 ms;
  - `src/api.f90`: the contract as a function `(method, path) → reply`;
    `src/store.f90`: open, migration runner, read of the single row;
    `src/metrics.f90`, `src/log.f90` (JSON, UTC timestamps computed in
    Fortran), `src/trace.f90`; `src/service.f90`: configuration, start-up
    checks, handler, shutdown; `src/main.f90`: the program;
  - `migrations/0001_digit.sql`: table `digit` with the seed `2|2|3|0`;
  - `tests/test_digit.f90`: 67 checks against the real migrations.
- **Image stages**: toolchain (Alpine 3.22.2, gfortran, SQLite, Python
  with FORD 7.0.13 and fprettify 0.3.7, all packages pinned), lint
  (fprettify including its warnings, full compile and link with every
  gfortran warning an error), test (`-fcheck=all`), doc-coverage (FORD with
  `warn: true`, any warning fails), api-docs (FORD HTML), build, runtime
  (18.3 MB, UID 10001).
- **Repository**: `scripts/lib/doc-definitions.psv` has a `fortran` row (a
  `!>` comment before every top-level module and program).
- **Compose**: `digit-2` on the `services` network only, volume
  `digit-2-data`, no database password.
- **Documentation**: README, all ten documents of `CLAUDE.md` 6.5.5 with
  real content (runbook entry for slow answers), API.md, ADR-0024.

## Decisions
- ADR-0024: no wrapper; a Fortran HTTP server over POSIX sockets, one
  connection and one request at a time; Linux constants and the `dirent`
  offset; state in a module so that no trampoline (executable stack) is
  generated; lint compiles fully; FORD `warn: true` as the coverage gate
  with inline `!!` docs for locals and one documented block per C
  interface.
