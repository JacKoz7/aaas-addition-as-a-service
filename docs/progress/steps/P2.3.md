## Goal
`digit-0` in C with its own SQLite database: the reference implementation
of `contracts/http/digit.yaml` that the other nine digit services follow.
Result: digit 0.

## What Was Done
- **Service `services/digit-0`** (C17, GCC 14, libmicrohttpd 1.0.1,
  SQLite 3.49.2), scaffolded with `scripts/new-service.sh digit-0 c`:
  - `src/api.c`: the contract as a pure function `(method, path) → reply`:
    `/value`, `/next`, `/health`, `/metrics`, problem details for 404, 405
    (`Allow: GET`) and 503; the row is read on every request and must name
    `AAAS_DIGIT`;
  - `src/store.c`: open, migration runner (`schema_migrations`, one
    transaction per file), read of the single `digit` row;
  - `src/metrics.c`: `digit_requests_total{digit,endpoint,outcome}`,
    `digit_build_info`; `src/log.c`: JSON logs of `CLAUDE.md` 6.1;
    `src/trace.c`: `traceparent` parsing; `src/main.c`: configuration,
    start-up checks, single-threaded server, SIGTERM shutdown;
  - `migrations/0001_digit.sql`: table `digit` with the seed `0|0|1|0`;
  - `tests/test_digit.c`: 52 checks against the real migrations,
    including the proof that answers follow the database row.
- **Image stages**: toolchain (Alpine 3.22.2, all packages pinned), lint
  (clang-format, clang-tidy with every finding an error, gcc `-Werror`),
  test, doc-coverage (Doxygen, `WARN_AS_ERROR`, static definitions
  included), api-docs (Doxygen HTML), build, runtime (26.5 MB, UID 10001).
- **Compose**: `digit-0` on the `services` network only, volume
  `digit-0-data`, no database password (embedded SQLite), healthcheck on
  `/health`.
- **Repository**: `.clang-format`, `.clang-tidy` and `Doxyfile` are known
  `#`-comment header styles (`templates/headers/styles.psv`).
- **Documentation**: README, all ten documents of `CLAUDE.md` 6.5.5 with
  real content, generated API.md (HTTP section from `digit.yaml`), ADR-0022.

  default `mem_limit` 64 MB kept.
