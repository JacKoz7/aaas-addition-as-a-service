## Goal
`digit-9` in Racket with its own SQLite database, following the reference
behaviour of `digit-0` (ADR-0022) and passing the shared contract test
`make contract-digit-9`. Its successor is 0 with a carry (`next = 0`,
`carry = true`). Result: the complete set of digits.

## What Was Done
- **Service `services/digit-9`**:
  - Racket 9.2 (Racket CS) from Alpine 3.24; the official Racket images
    are amd64 only. Scaffolded with `scripts/new-service.sh digit-9
    racket`.
  - At runtime only Racket's base library. SQLite is reached through the
    foreign function interface (`src/digit9/sqlite.rkt`): Racket's `db`
    library raised the memory of the process from about 72 MiB to
    142 MiB.
  - `src/digit9/server.rkt`: an accept thread and one Racket thread per
    connection, each under its own custodian; at most 256 connections; a
    lingering close (200 ms, 16 KiB); a graceful stop that wakes only the
    idle connections.
  - `src/digit9/http.rkt`: the framing of `digit-6` and `digit-8` over
    Racket ports:
    - line reading with a byte budget into one buffer per connection
      (4 KiB, at most 16 KiB);
    - heads up to 8 KiB (431 above);
    - bodies by Content-Length or chunked, up to 64 KiB (413 above; 400
      for ambiguous framing);
    - keep-alive and the 10 s idle timeout;
    - reply formatting and the request loop.
  - `src/digit9/memory.rkt`: the memory guard (a major garbage collection
    when the runtime holds 12 MiB more memory than after the previous
    one).
  - `src/digit9/service.rkt`: configuration, start-up checks, SIGTERM,
    SIGINT and SIGHUP as Racket breaks; `src/digit9/main.rkt` is the
    entry point of `raco exe`.
  - Also `api.rkt`, `store.rkt`, `metrics.rkt`, `log.rkt` and `trace.rkt`.
  - `migrations/0001_digit.sql`: table `digit` with the seed `9|9|0|1`.
  - Tests (`raco test`, 225 tests):
    - `tests/contract-test.rkt`: the contract and the migrations;
    - `tests/transport-test.rkt`: the framing over string ports and pipes,
      the trace context and the log lines;
    - `tests/server-test.rkt`: the server over TCP (keep-alive, stop,
      a request during the stop, connection limit, ended connections,
      resets, port in use) and the configuration;
    - `tests/examples-test.rkt`: every `> expression` example of every doc
      comment, evaluated inside its module.
  - `tools/docs.rkt`, `tools/doc-coverage.rkt` and `tools/api-docs.rkt`:
    the doc comment reader, the coverage gate (private definitions
    included) and the Scribble rendering of the API documentation.
- **Image stages**:
  - base: `alpine:3.24.3` with `racket` and `sqlite-libs`, pinned;
  - tools: compiler-lib, rackunit-lib, scribble-lib, typed-racket-lib and
    macro-debugger-text-lib from the Racket 9.2 release catalog; fmt,
    pretty-expressive and review from pinned Git commits; six packages
    that review's module table names, as sources only;
  - lint: `raco fmt --width 100` (the output must equal the file), a line
    limit of 100, `raco make` of every module, `raco review`;
  - test: `raco test tests`;
  - doc-coverage: `tools/doc-coverage.rkt` on every module;
  - api-docs: the Scribble HTML;
  - build: `raco exe` and `raco distribute`;
  - runtime: Alpine 3.24.3 with the libraries of the Racket runtime and
    SQLite, user 10001; 84 MB.
- **Compose**: `digit-9` on the `services` network only, 128m, exec-form
  healthcheck with busybox `wget`, volume `digit-9-data`; the scaffold's
  `data` network and database password were removed (SQLite is
  embedded).
- **Repository**: `.gitignore` ignores Racket's `compiled/` directories.
- **Documentation**: README, all ten documents of `CLAUDE.md` 6.5.5 with
  real content, API.md (generated sections by `make api-md`), ADR-0031.

    - unknown path: 404;

    - garbage: 400;

    - `Content-Length: 70000`: 413;
    - a chunked body and then a GET: 405 then 200;
    - `Content-Length` with `Transfer-Encoding`: 400;
    - HTTP/1.0: `Connection: close`;
    - HTTP/2 preface: 400.
  - **Slow client:** a half-sent request line does not delay another
    client (0.2 ms) and is closed after 10.0 s.
  - **Connection limit:** 256, 257 and 300 connections, 256 answered each
    time.
  - **Resets:** 100 connections reset mid-request, then 200.
  - **Floods:** two clients each opened 256 connections with 1 MB heads.
    - First build: ten rounds reached a `memory.peak` of 125 MiB of
      128 MiB, and the process kept 111–119 MiB afterwards; its live heap
      was about 71 MiB. Racket CS keeps the memory freed by minor
      collections mapped until a major collection.
    - One reused input buffer per connection: peak 114 MiB.
    - With the memory guard: ten rounds, 69–74 MiB after each round,
      `memory.peak` 86.1 MiB; the service stayed healthy.
  - **Database:** with table `digit` renamed, `/value`, `/next` and
    `/health` answered 503, with `no such table: digit` in the error line.

  - **Debug log:** `AAAS_LOG_LEVEL=debug` gave the request line with the
    caller's `traceId` and `spanId`.
